# 地质资料数据治理工具 开发设计说明

版本 0.2，2026-10-19，适用于 V1.0 开发。0.2 版补充实现中的调整，见第 13 节。依据《数据治理程序开发需求说明》《历史存档资料落库目录结构与文件命名说明》v3 和工作设计 v2 第四章第四节。

## 1 V1.0 范围

1）适配对象为现行报盘资料，覆盖两种样例形态。

| 形态 | 样例 | 目录入口 | 识别特征 |
|---|---|---|---|
| 现行报盘 XML 型 | Edmaker2017 | 管理性文件/地质资料文件目录.xml | 存在管理性文件目录，XML 根节点 AJXX 且带 SysVersion |
| 现行报盘 登记表型 | 新标准/dzwd001、新标准/新标准例子/6933 | 源电子文件/电子文件登记表.html | 存在存档电子文件、源电子文件两个目录和电子文件登记表，无管理性文件 |

2）V1.0 跑通八步流程，扫描对账、时期识别、目录解析、项目关联、阶段分类、命名与转换、输出与校验、涉密分套。

3）界面实现工作台、档案盘点、人工复核三个模块，其余五个模块保留菜单入口和占位页，V1.x 补齐。

4）近期报盘、清欠期、早期图文三个时期在 V1.0 中只做到识别并标记为暂不支持，解析器以插件形式预留，V2.0 至 V4.0 依次补齐。

## 2 读样例时发现的情况

以下情况影响程序设计，需要通过项目经理向甲方或全国馆确认，程序先按括号外的口径处理并做成配置。

1）新标准样例的登记表名为成果地质资料电子文件登记表，形成日期为 2006 年和 2007 年，目录组织与 SZ1999002-2001 汇交格式一致，没有 XML 和管理性文件。它可能实际属于清欠期或早期标准的电子化形态。V1.0 先按现行报盘登记表型处理，时期标签在规则配置里可改。
2）Edmaker2017 样例的存档电子文件、源电子文件两个目录为空，只有管理性文件。程序据 XML 生成文献清单后，物理文件缺失的条目标记为待处理并进入问题台账。测试时在临时目录按 XML 补造占位文件，验证完整落库链路。
3）两个样例都没有 ML 文件，与每档至少有 ML 的口径不一致。V1.0 把 ML 作为可选目录入口，有则解析并与 XML 互校，无则不报错。
4）交接清单中档号为数值型，五组样例文件夹名均不在清单内，对账时这些档会显示为清单外档案。程序按文本处理档号，清单中的数值统一转文本比对，前导零以文件夹名为准。
5）XML 中存在 MJ 为机密级的案卷和密级为机密、秘密的附图条目，非涉密套输出时据此剔除。
6）题名中常见的 1∶5万 写法使用比例号 ∶，Windows 文件名禁止半角冒号，命名规则把半角冒号替换为比例号，比例号保留。

## 3 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.11 及以上 | 开发效率高，离线打包成熟 |
| 界面 | PySide6 | Qt 官方绑定，LGPL，可离线打包 |
| 数据库 | SQLite，WAL 模式 | 单机零部署，单文件便于备份和交接 |
| 规则配置 | YAML，UTF-8 | 可读可注释，业务人员能看懂 |
| XML 和 HTML 解析 | lxml | 容错好，支持 GBK 和 GB2312 |
| Excel | openpyxl | 读交接清单、写目录和映射表 |
| PDF 与影像 | PyMuPDF、Pillow | 页数校验、V4.0 多页影像合成 PDF |
| 打包 | PyInstaller 单目录模式 | 生成离线安装目录，无需联网安装依赖 |

Word 转 PDF 按优先级依次尝试，第一个可用的转换器生效，全部不可用时该文件进入待处理并说明原因。

1）Microsoft Word，经 COM 接口调用，需要涉密机已装 Office。
2）WPS 文字，经 KWPS.Application COM 接口调用，国产化环境常见。
3）LibreOffice 便携版，命令行无界面转换，可随安装包离线提供，作为兜底。
4）存档电子文件中已有同名 PDF 时优先直接使用存档 PDF，不做转换。现行报盘资料大多属于这种情况，实际需要转换的文件很少。

解析器插件接口如下，新增时期只需新增一个插件并在规则配置中登记识别特征，不改流程代码。

```python
class Parser(Protocol):
    code: str            # 时期代码，如 xianxing_xml
    def can_parse(self, archive: ArchiveScan) -> float: ...   # 返回置信度
    def parse(self, archive: ArchiveScan) -> ParseResult: ... # 案卷字段与文献清单
```

文献清单每条包括题名、题名来源、类别代码、册号件号、对应物理文件即存档文件与源文件、页图范围、密级、阶段参考字段、原始节点信息。

## 5 每档八步处理

| 步 | 内容 | V1.0 实现要点 |
|---|---|---|
| 1 扫描对账 | 列目录结构、定位目录文件、按类别代码计数，与交接清单核对 | os.scandir 流式遍历，不打开不哈希文件；结果分一致、数量差异、目录缺失、清单外四种 |
| 2 时期识别 | 按规则特征打分 | 得分最高且超过阈值才定时期，否则标人工 |
| 3 目录解析 | 调用对应解析器 | XML、登记表、ML 三类入口，互校题名和数量 |
| 4 项目关联 | 用项目名称、编号、年度匹配 GRP 项目对照表 | 编号或名称完全一致为确定匹配，名称相似为疑似匹配进人工，无对照表或未命中为未匹配 |
| 5 阶段分类 | 规则库打分，输出阶段、子目录、文件类型、依据、置信度 | 依据不足、冲突、低于阈值的进人工复核队列 |
| 6 命名与转换 | 四段式命名，Word 转 PDF | 存档 PDF 直接复制，期间标识取不到的进人工 |
| 7 输出与校验 | 写落库目录，第六章正则和五项校验 | 校验不过的文件不写入落库目录，记录原因 |
| 8 涉密分套 | 全补、涉密、非涉密三套 | 非涉密套输出前二次校验，发现涉密条目即中止该套输出 |

去向状态按需求说明分为已落库、关联保存、原始区保留、待处理。附图、附表、附件、数据库等成果组成部分的去向待甲方确认，V1.0 默认在映射表登记为关联保存，配置项可改为随成果报告落入成果评审阶段。原始资料默认登记为原始区保留，文件数超过阈值的目录按目录登记一行并写明文件数。

## 6 数据表

SQLite 单库，路径在系统设置里配置，默认放在成果区下。

| 表 | 主要字段 | 用途 |
|---|---|---|
| batch 批次 | 批次号、档号区段、程序版本、规则版本、状态、开始结束时间、操作人 | 按区段分批、断点续跑 |
| handover 交接清单 | 批次表名、序号、档号、九类件数、十类件数、文件数、文件夹数、数据量 | 对账依据 |
| archive 盘点台账 | 档号、根路径、时期、时期依据、目录入口、实扫文件数、文件夹数、容量、类别分布、对账状态、处理状态 | 资料底数与时期分组 |
| document 文献清单 | 档号、序号、题名、题名来源、类别代码、册号件号、存档文件、源文件、密级、阶段参考 | 分类与提取的输入 |
| project 项目对照表 | 项目 UUID、项目名称、项目编号、层级、年度、来源文件 | 项目关联 |
| archive_project 档案项目关联 | 档号、项目 UUID、匹配状态、匹配依据、确认人 | 一档多项目、一项目多档 |
| mapping 映射记录 | 需求说明表 4-1 全部字段，外加规则版本、置信度、批次号 | 生成映射关系表 |
| review 复核队列 | 映射记录号、进入原因、候选结果、状态、确认结果、确认人、复核人、时间 | 人工复核与回写 |
| issue 问题台账 | 编号、档号、类型、描述、处理意见、责任人、状态 | 质量闭环 |
| oplog 作业日志 | 时间、批次、档号、步骤、级别、消息、操作人 | 全程留痕与工作量统计 |
| rule_version 规则版本 | 版本号、各规则文件摘要值、加载时间、评审记录 | 结果可追溯到规则版本 |
| decision 人工结论 | 档号、文献标识、结论、确认依据、确认人、复核人 | 重跑时优先采用，保证人工结论不丢 |
| case_info 案卷字段 | 档号、目录解析出的案卷字段、来源文件 | 结构化目录 Excel 取值 |

重跑口径。同一档在同一规则版本下重跑时，先删除该档在成果区和数据库中的旧结果再重新生成，人工复核已确认的结论保留并优先采用，因此重跑结果稳定一致。

## 7 规则配置格式

rules 目录下每个文件带 version 字段，ruleset.yaml 汇总版本号，程序启动时计算每个文件的摘要值登记到 rule_version 表，映射表每行写入规则版本号。

| 文件 | 内容 |
|---|---|
| ruleset.yaml | 规则集版本号、各文件清单、全局参数如置信度阈值、附件去向、原始资料登记阈值 |
| periods.yaml | 四个时期及子形态的识别特征、权重、对应解析器 |
| stages.yaml | 九个阶段、固定子目录、期间标识类型、二级三级第 4 阶段名称差异、文件类型受控词表、版本受控词 |
| classify.yaml | 分类规则，每条含阶段、子目录、文件类型、题名关键词、排除词、类别代码约束、来源约束、权重 |
| naming.yaml | 项目名称清洗规则、字符替换表、长度上限、版本体系、默认版本词 |
| excel_header.yaml | 结构化目录 Excel 表头，每列含列名、取值来源优先级、缺失标记 |
| secrecy.yaml | 涉密密级词、非涉密密级词、目录级涉密关键词、分套口径 |
| validation.yaml | 第六章目录正则、三类文件名正则、五项校验开关 |

分类规则示例如下，程序代码里不写业务关键词。

```yaml
- id: S-CGPS-01
  stage: 成果评审
  subdir: 成果评审
  file_type: 成果评审意见
  categories: [S]
  keywords: [评审意见书, 成果报告评审意见, 评审备案证明]
  exclude: [设计, 野外验收, 任务书]
  weight: 0.9
```

置信度计算。命中关键词得规则权重，命中排除词该规则作废，类别代码不符该规则作废，来源约束不符降权。取得分最高的规则，最高分低于阈值、最高分与次高分差距小于冲突阈值、或无规则命中时进入人工复核，映射表记录全部候选和命中词。

## 8 落库与命名

1）路径为 成果区/全补/二级项目或三级项目/{UUID}/阶段/[固定子目录]/文件名。项目未匹配的档不进入 GRP 目录，写入成果区/待匹配/{档号}/ 下供人工核对，映射表去向为待处理。
2）项目名称优先取 GRP 项目对照表中的正式名称，其次取 XML 的 XMMC，再次取登记表的报告题名并标注来源，按 naming.yaml 清洗。
3）期间标识，年度性阶段取文书业务年度，来源依次为文号中的年份、XML 的批复时间或形成时间，取不到进人工；质量监督写作 YYYY年M月；一次性阶段无期间标识；资料汇交暂按一次性阶段。
4）版本体系默认文字型，默认版本词按文件类型配置，例如评审意见、批复为定稿，报告为终审。同一阶段同一期间同一文件类型出现多份时，整个项目改用数值型 v1、v2，并把这些文件送人工复核确认。
5）校验覆盖第六章 6.1 目录正则、6.2 三类文件名正则、6.3 五项要点，以及文件名不超过 120 字符、全路径不超过 255 字符。

## 9 输出物

1）落库成果，全补、涉密、非涉密三套目录。涉密和非涉密两套默认以硬链接派生，跨盘或不支持硬链接时复制，节省成果区空间。
2）结构化目录 Excel，表头按 excel_header.yaml 生成，每格同时可导出来源说明表。
3）映射关系表 Excel，每个源文件一行，字段按需求说明表 4-1。
4）质检结果 Excel，按八项校验列出通过数和未通过明细。
5）盘点台账 Excel，含对账结果和时期识别依据。

## 10 界面

八个模块按工作设计原型布局，V1.0 完成以下三个。

1）工作台。四张指标卡为移交档案数、已完成治理档数、待人工复核件数、未关闭问题数；中部为四个时期进度和九个阶段落库文件分布；底部为最近批次。
2）档案盘点。选择数据目录、导入交接清单、启动扫描；左侧按时期和对账状态筛选，右侧盘点列表，下方显示时期判定依据、目录文件、类别分布、对账差异。扫描在后台线程运行，可中止。
3）人工复核。左侧待复核队列及进入原因；中部原文信息和文件路径，提供调用系统默认程序打开原文的按钮；右侧显示程序建议、候选阶段、命中依据、置信度，下方确认阶段、子目录、文件类型、期间标识、版本并填写确认依据，确认后回写映射记录并重新生成该文件的落库结果。

## 11 测试

1）单元测试覆盖命名清洗、三类文件名正则、目录正则、分类打分、XML 和登记表解析、交接清单读取。
2）样例回归测试读取数据示例目录，目录位置由环境变量 DGT_SAMPLE_ROOT 指定，缺失时跳过。Edmaker2017 和新标准三档的期望结果固化为测试快照，包含时期、文献数、每条文献的阶段与文件类型、落库文件名，规则或代码变化导致快照变化时测试失败。
3）合成样例测试在临时目录按程序生成虚构档案，不依赖真实资料，保证仓库内测试可独立运行。
4）仓库不包含任何移交资料和样例数据，.gitignore 排除样例、成果区、数据库、缓存和打包产物。

## 13 实现中的调整

1）版本默认词。落库说明第五章示例中同一项目混用 v1 与 终审，与约束一冲突。V1.0 默认文字型，历史存档资料取 终审 或 定稿，备案类取 备案稿；同一档内同阶段、同期间、同文件类型出现多份时，该档整体改用数值型 v1、v2。跨档的版本体系一致性由质检中的版本连续性项检查。
2）资料汇交词表。为避免多份管理性文件同名，暂定词表扩为 汇交汇总表、资料目录、档案文件目录、目录著录表、实物资料目录清单、电子文件登记表、涉密情况报告表、载体外标签、汇交凭证，待开发单位确认。
3）格式不在落库扩展名范围的文件，如目录 XML、EPS 附图，登记为关联保存，不参与版本编号。
4）项目层级未知时，第 4 阶段显示为 实施方案或年度设计，文件不落库，进待匹配区。
5）登记表型无密级字段，按 secrecy.yaml 的 empty_as 从严处理，全部进涉密套。待甲方确认口径后可改为 public。
