# 地质资料数据治理工具 操作说明

适用版本 V1.0。本说明面向驻场作业人员和技术负责人。V1.0 能完整治理现行报盘资料，近期报盘、清欠期、早期图文资料在盘点时能识别，治理时显示暂不支持。

## 1 安装与启动

### 1.1 免安装版

1）把 `地质资料数据治理工具_V1.0.0.zip` 解压到本地硬盘，例如 `D:\地质资料数据治理工具\`。路径中可以有中文，不要放在移交资料所在的盘符目录内。
2）双击 `地质资料数据治理工具.exe` 启动，不需要安装 Python。
3）文件夹中的 `rules` 是规则配置，`_internal` 是运行库，都不要删除或移走。

### 1.2 源码版

在程序目录中执行以下命令。

```
pip install -r requirements.txt
python run_gui.py
```

### 1.3 首次启动设置

程序先打开主界面，随后弹出设置框。

1）工作区目录。存放程序数据库和成果区，治理结果全部写在这里。选一个空间充足的本地目录，例如 `D:\数据治理工作区`，不要选在移交资料目录内。
2）操作人姓名。写入作业日志和人工确认记录，用于工作量统计和追溯。

以后可在 系统设置 页点 切换工作区 修改，也可以直接改当前操作人。

## 2 界面总览

左侧为八个功能模块，底部状态栏显示操作人、规则版本和工作区。

| 模块 | 用途 | V1.0 状态 |
|---|---|---|
| 工作台 | 总体进度、分时期进度、九阶段文件分布、最近批次、每日工作量 | 完整 |
| 档案盘点 | 导入交接清单和项目对照表、扫描对账、时期识别、治理选中档 | 完整 |
| 规则管理 | 查看规则配置和版本登记 | 只读查看 |
| 批量治理 | 按档号区段运行批次、断点续跑 | 简版 |
| 人工复核 | 处理程序拿不准的文件 | 完整 |
| 质量检查 | 落库规范校验、映射完整性、涉密分套检查 | 简版 |
| 成果输出 | 生成全补、涉密、非涉密三套成果 | 简版 |
| 系统设置 | 工作区、操作人、转换器状态、作业日志 | 简版 |

## 3 标准作业流程

### 3.1 导入交接清单

进入 档案盘点 页，点 导入交接清单，选择《地质资料数据交接清单.xlsx》。程序读取两个工作表的全部档号和各类件数，自动跳过表尾说明行。导入一次即可，清单更新后重新导入会覆盖。

### 3.2 导入 GRP 项目对照表

点 导入项目对照表，选择 GRP 开发单位提供的项目清单，支持 xlsx 和 csv。表头需包含以下列，列名可以是括号中的任一写法。

| 字段 | 可识别的列名 | 要求 |
|---|---|---|
| 项目UUID | 项目UUID、UUID、项目ID | 32 位十六进制，带不带连字符均可 |
| 项目名称 | 项目名称、名称 | 正式全称 |
| 项目编号 | 项目编号、编号、项目代码 | 可空 |
| 项目层级 | 项目层级、层级、项目级别 | 二级项目或三级项目 |
| 年度 | 年度、项目年度 | 可空 |

没有项目对照表时也可以盘点和试运行，但所有档都会显示 待项目关联，文件只登记不落库。导入对照表后对这些档重新治理即可。

### 3.3 扫描盘点

1）在 数据目录 处点 选择…，选中移交资料所在目录，即各档号文件夹的上一级。
2）点 开始扫描。程序逐档统计文件数、文件夹数、容量和各类别件数，识别时期，并与交接清单对账。扫描只读不写，不打开文件内容。
3）扫描过程中可点 中止，已扫描的档保留结果，下次扫描时重新统计。
4）左侧可按时期和对账状态筛选；选中某档后，下方显示时期判定依据、目录文件、类别分布和对账差异。

对账状态的含义如下。

| 状态 | 含义 | 处理 |
|---|---|---|
| 一致 | 文件数、文件夹数、类别件数与清单一致 | 无需处理 |
| 数量差异 | 存在差异，差异明细见详情 | 核实后登记问题，必要时向甲方确认 |
| 清单外 | 文件夹在清单中查不到 | 核实档号 |
| 目录缺失 | 清单有该档，数据目录中没有文件夹 | 核实移交是否完整 |
| 文件不可读 | 部分文件或目录无法读取 | 检查权限或介质 |

发现问题时选中该档，点 登记问题 记录到问题台账。

### 3.4 运行治理

两种方式任选。

1）在 档案盘点 页选中一档或多档，点 治理选中档。不选时会询问是否对当前筛选结果全部运行。
2）在 批量治理 页填起始档号和终止档号，点 运行批次。已完成且规则版本未变的档自动跳过，因此中断后再次运行即为断点续跑；需要全部重做时点 强制重跑区段。

每档依次完成目录解析、项目关联、阶段分类、命名、Word 转 PDF、落库和校验。处理状态含义如下。

| 处理状态 | 含义 |
|---|---|
| 已完成 | 全部文件已落库或已登记去向 |
| 待复核 | 有文件需要人工确认 |
| 待项目关联 | 项目未匹配，导入或补充项目对照表后重跑 |
| 暂不支持 | 近期、清欠、早期时期，待后续版本 |
| 失败 | 程序出错，原因见处理说明和作业日志 |

### 3.5 人工复核

进入 人工复核 页处理程序拿不准的文件。左侧为待复核队列，注明进入原因，常见原因如下。

1）置信度低于阈值，规则命中但依据不足，例如题名只有 审查意见。
2）未命中任何分类规则，例如 内审意见书、初审意见书。
3）期间标识缺失，年度性阶段的文件题名中取不到年份。
4）疑似匹配，项目名称与对照表相似但不完全一致。

操作步骤如下。

1）在左侧选中一条，中部显示文件题名、来源、类别和路径，PDF 可直接预览。其他格式点 用系统程序打开副本，程序会先复制到成果区临时目录再打开，不会改动原件。
2）右上方查看程序建议、命中依据和候选结论，双击候选可直接填入下方表单。
3）在下方确认阶段、子目录、文件类型、期间标识和版本。期间标识的写法：年度性阶段填四位年份如 2026，质量监督填 2026年3月，一次性阶段留空。版本一般保持 按规则自动。
4）不属于九个阶段落库范围的文件，阶段选 关联保存（不落库），只在映射表登记。
5）填写确认依据，例如 核对原文首页为2006年度工作方案，然后点 确认落库。程序立即对该档重新治理，确认结论永久保存，以后重跑也会沿用。
6）自己拿不准的点 提交技术负责人；发现资料本身的问题点 登记问题，汇总后经项目经理向全国馆请教。

项目关联类条目在 关联项目 下拉框中选择正确项目后点 确认关联。

### 3.6 质量检查

进入 质量检查 页点 执行校验，共九项。

| 校验项 | 内容 |
|---|---|
| 交接清单对账 | 各档对账状态 |
| 目录路径正则 | 落库说明 6.1 目录规则 |
| 文件名正则 | 落库说明 6.2 三类命名规则，长度不超过 120 字符、路径不超过 255 字符 |
| 受控词表 | 文件类型和版本名称在词表内 |
| 版本连续性 | 数值型版本从 v1 起连续，同一项目不混用两种版本体系 |
| 唯一性 | 同一阶段目录内不重名 |
| 映射表完整性 | 每份文献都有映射记录，必填字段齐全，落库文件确实存在 |
| PDF可读与页数 | 落库 PDF 能打开且页数大于 0 |
| 涉密分套 | 每条记录都有涉密标记，档级涉密的档没有非涉密记录 |

未通过明细列在下方，按说明逐项整改后重新校验。

### 3.7 成果输出

进入 成果输出 页点 生成三套成果，输出到 `工作区\成果区\导出\日期时间\`，内容如下。

```
导出\20261020_093000\
├── 全补\
│   ├── 落库成果\二级项目或三级项目\{UUID}\阶段\文件
│   ├── 结构化目录_全补.xlsx
│   └── 映射关系表_全补.xlsx
├── 涉密\      同上
├── 非涉密\    同上
├── 质检结果.xlsx
└── 盘点台账.xlsx
```

非涉密套输出前会重新判定每条记录的密级，发现任何涉密内容即中止该套输出，界面会提示。没有密级字段的资料按从严口径归入涉密套。

## 4 输出文件说明

1）映射关系表。每个源文件一行，包括未落库的文件，记录源路径、题名及来源、时期、项目、阶段、文件类型、治理后路径、处理方式、去向状态、判定依据、规则版本、密级和人工确认人。去向状态分为 已落库、关联保存、原始区保留、待处理。
2）结构化目录。每个落库文件一行，表头由 `rules\excel_header.yaml` 配置。取不到值的格子填 【缺失】，取值来源 工作表记录每格取自哪个字段。
3）质检结果。校验汇总和未通过明细。
4）盘点台账。每档的时期、目录入口、文件数、对账结果和处理状态，也可在 档案盘点 页点 导出盘点台账 单独导出。

## 5 规则调整

规则全部在 `rules` 文件夹中，用记事本或其他文本编辑器打开，保存为 UTF-8 编码。

| 文件 | 内容 |
|---|---|
| ruleset.yaml | 规则集版本号、置信度阈值、附件去向、转换器顺序、项目表列名 |
| periods.yaml | 四个时期的识别特征 |
| stages.yaml | 九个阶段、子目录、期间标识类型、文件类型受控词表、默认版本词 |
| classify.yaml | 分类规则，含关键词、排除词、类别代码约束和权重 |
| naming.yaml | 项目名称清洗、期间标识提取、扩展名范围、长度上限 |
| excel_header.yaml | 结构化目录表头及取值来源 |
| secrecy.yaml | 涉密密级词、目录级涉密关键词、分套口径 |
| validation.yaml | 落库说明第六章校验正则 |

修改规则的要求如下。

1）规则由技术负责人修改，修改后在 ruleset.yaml 中提升 version 并在 changelog 记录修改内容。
2）重启程序后生效，规则版本自动登记，映射表每行记录所用规则版本。
3）规则变化后在 批量治理 页对受影响区段运行批次，程序会自动重做规则版本不同的档，人工确认过的结论保留。

## 6 注意事项

1）程序对移交资料只读，所有写操作限定在工作区成果区内，任何功能都不会修改或删除原始档案。
2）离线单机运行，不访问网络。
3）Word 转 PDF 依次使用本机 Word、WPS、LibreOffice，系统设置 页显示当前可用的转换器。都没有时 Word 文件进入待处理，存档区已有 PDF 的不需要转换。
4）多人作业时每人使用自己的工作区，或轮流使用同一工作区，不要两台电脑同时打开同一个工作区。
5）定期备份工作区中的 `dgt.sqlite`，其中保存了盘点台账、映射记录、人工结论和作业日志。

## 7 常见问题

| 现象 | 原因与处理 |
|---|---|
| 所有档显示 待项目关联 | 未导入 GRP 项目对照表，或对照表中没有对应项目 |
| 大量文件显示 文件缺失 | 目录中登记的文件在档内找不到，核实移交是否完整，并在问题台账登记 |
| Word 文件 转换失败 | 本机没有 Word 或 WPS，或文件损坏；安装转换器后重跑该档 |
| 时期显示 待人工判别 | 目录特征不完整或同时符合多个时期，登记问题后由技术负责人判断 |
| 一档显示 暂不支持 | 属于近期、清欠或早期时期，等待 V2.0 至 V4.0 |
| 启动报错缺少模块 | 免安装版文件不全，重新完整解压 |
